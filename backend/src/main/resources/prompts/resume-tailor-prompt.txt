STEP 1 — KEYWORD EXTRACTION (TECHNICAL & ROLE-SPECIFIC ONLY)
---------------------------

Read the job description and extract ONLY keywords that are concrete, specific, and scannable
by an ATS system. These are terms a hiring manager explicitly filters candidates on.

✅ ALWAYS INCLUDE:
  • Programming languages          e.g. Python, Java, SQL, TypeScript, Go, Scala, C#, Kotlin
  • Frameworks & libraries         e.g. React, Vue.js, Angular, Spring Boot, Node.js, Django, FastAPI, Next.js
  • Tools & platforms              e.g. Docker, Kubernetes, Jenkins, GitLab, Terraform, Ansible
  • Cloud services & products      e.g. AWS, Azure, GCP, S3, EC2, Lambda, Snowflake, Databricks, DBT
  • Databases & data stores        e.g. PostgreSQL, MySQL, MongoDB, Redis, Cassandra, SQL Server, Elasticsearch
  • Messaging & streaming          e.g. Kafka, RabbitMQ, SQS, Pub/Sub
  • Protocols & standards          e.g. REST, RESTful APIs, GraphQL, gRPC, OAuth2, WebSockets
  • Architecture patterns          e.g. Microservices, Event-Driven Architecture, Serverless, CI/CD
  • Engineering practices          e.g. TDD, BDD, Agile, Scrum, full SDLC, code review, pair programming
  • Certifications & degrees       e.g. AWS Certified, CPA, PMP, Bachelor of Science
  • Versioning & DevOps tools      e.g. Git, GitHub, GitLab, JIRA, Confluence
  • Domain-specific acronyms       e.g. ETL, ELT, SPA, SDK, API, ORM, MVC
  • Specific job title from JD     e.g. "Full Stack Software Engineer", "Senior Backend Engineer"

❌ NEVER INCLUDE — these are vague quality/soft descriptors, not ATS-scannable keywords:
  • Generic adjectives             e.g. high-quality, scalable, reliable, robust, modern, clean
  • Vague outcome phrases          e.g. execution speed, platform flexibility, delivery excellence
  • Generic soft skill phrases     e.g. cross-functional collaboration, strong communicator,
                                       ability to learn, team player, fast learner, self-starter
  • Filler job posting language    e.g. "duties as assigned", "other responsibilities",
                                       "fast-paced environment", "detail-oriented", "results-driven"
  • Generic process words          e.g. iterative development, best practices, creative solutions,
                                       innovative thinking, stakeholder management
  • Experience level descriptors   e.g. "2-4 years experience", "entry level", "senior level"

DECISION RULE — before adding any keyword ask:
  "Would a recruiter type THIS EXACT TERM into a search filter or ATS keyword field?"
  If NO → exclude it.
  If YES → include it with exact JD wording.

Additional rules:
  - Use exact wording from the JD (preserve casing, hyphens, spacing).
  - Multi-word technical phrases are a single keyword: "Spring Boot", "RESTful APIs", "full SDLC".
  - If both an acronym and its full form appear in the JD, include both separately.
  - Limit extractedJdKeywords to genuine technical/role-specific terms only.

Store the result as: extractedJdKeywords[]

---------------------------
STEP 2 — RESUME GENERATION
---------------------------

Using ONLY the candidate data as the source of truth for facts (companies, dates, education),
generate a complete tailored resume with the following character targets for ATS density:

  Professional Summary : 300–450 characters
  Experience Section   : 2800–4000 characters total across all roles
  Skills Section       : 450–650 characters

A. PROFESSIONAL SUMMARY (2–3 sentences, no "I"):
   - State the exact job title from the JD verbatim
   - Name the candidate's primary technologies aligned with the JD
   - Reference key engineering practices and cloud/platform alignment if present

B. EXPERIENCE BULLETS — per role:
   Recent/current role  → 6–9 bullets, 1000–1400 chars
   Mid-level role       → 4–6 bullets,  700–900  chars
   Older role           → 3–4 bullets,  500–750  chars

   Every bullet must:
   - Start with a strong action verb
   - Include at least one keyword from extractedJdKeywords
   - Quantify impact where defensible (%, latency, scale, throughput)
   - NOT fabricate companies, roles, or dates

C. SKILLS SECTION (450–650 characters):
   - Organize into named categories: Languages, Frameworks, Databases, Cloud & DevOps, Tools, Methodologies
   - Every keyword in extractedJdKeywords that is defensible for this candidate MUST appear
     in Skills, Summary, or an experience bullet — use exact JD wording

D. EDUCATION & CERTIFICATIONS:
   - Copy verbatim from candidate data — do not alter
